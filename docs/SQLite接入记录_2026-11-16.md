# SQLite 接入记录

## 完成内容

- v1.3.0 桌面版以 SQLite 保存课程、上课安排、作业和设置，网页模式保留 localStorage。
- 主进程负责数据库，预加载层仅暴露受限初始化/保存接口；页面只在写入确认后更新状态。
- 首次迁移前保存原 JSON，保留旧 localStorage；成功后用数据库初始化标记避免重复导入。
- 课程与作业 ID、关联、配色、备注、周次、提醒设置及已提醒记录保留。
- 导入、覆盖、重置使用事务；数据库错误不显示成功，原状态及导入预览保留。
- 开发数据库与正式数据库分开，真实数据库及备份排除在 Git 之外。

## 验证及边界

- `npm test`：29 项测试及学校课表提取器测试通过。事务中途写入失败使用明确标注的故障注入测试，不是自然发生的 AI 失败。
- 使用当前课表的私有备份在独立用户目录测试，核对 24 门课程、45 个时段与原数据一致。
- 真实 Windows EXE 读取/写入 SQLite 成功，页面重载后读取新设置；模拟作业的 Windows 通知已返回显示成功，已提醒时间写入 SQLite。
- 完全退出后重新启动，读取原 SQLite 数据及已提醒记录；通过真实设置页导入 JSON 备份后，再次重启最终便携 EXE，课程、学期及提醒记录仍一致。
- 旧版实际用户目录仅额外保存迁移前 JSON 备份；实际数据库升级在用户退出旧版并首次启动新版后完成。独立测试数据不混入用户正式数据。
- 不增加账号系统或云同步。其他机器、其他 Windows 用户需通过 JSON 备份迁移。

## 实际遇到的问题

打包首次在 PNG 转 ICO 工具退出时失败，进程退出码为 3221226356，日志同时显示 ICO 已生成。核验生成 ICO 的文件头后，将该 ICO 加入 `build/icon.ico`，打包配置直接引用，避免再次调用异常退出的转换器。随后打包完成。

补充校验后的一次重新打包遇到 Electron 下载连接失败。改用已经安装并验证版本的 `node_modules/electron/dist`，通过 `electron-builder --win portable --config.electronDist=node_modules/electron/dist` 复用本地运行时完成打包；未关闭 TLS 校验。

一次实机验证脚本使用 `document.body.innerText` 检查输入框的学期名称，断言失败；输入框值不属于 innerText。改为检查输入框 value 后验证通过。此问题属于验证脚本，不是产品数据库读取失败。

自动审批拒绝关闭用户当前旧版实例，改用独立端口、独立用户目录验证，保留用户正在运行的程序。
